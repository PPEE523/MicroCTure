# MicroCTure 项目分析与实施路线

分析日期：2026-09-21。依据：项目内 15 页《基于深度学习的接触矩阵处理实践方案.pdf》、两个 `.cool` 文件的 HDF5 元数据及 Excel 标注表。本文是实施建议，不代表已经完成模型或发现新结构。

## 1. 先确定要交付什么

项目要把 Micro-C 接触矩阵变成可解释的结构识别与候选发现结果。矩阵两条轴都是基因组位置，每个格子记录两个位置的接触次数；局部矩阵里的形状是模型要学习的对象。

PDF 第 8 页“必做与选做各一”的文字容易产生歧义，但按 6.1/6.2 的分节和分值，稳妥的实施范围是：必做任务一、二、三全部完成，再从四、五、六中选一个。

| 任务 | 分值 | 要解决的问题 | 最小交付 |
|---|---:|---|---|
| 一：已知结构识别 | 40 | 一个已知结构窗口属于 OPCID、CHIN 还是 CHID？ | 分类模型、留出集准确率和混淆矩阵、显著性图 |
| 二：新结构发现 | 30 | 有没有不属于现有注释、形状有规律且重复可见的区域？ | 候选坐标、聚类、重复一致性指标、统一色标热图 |
| 三：多轨道可视化 | 10 | 不同条件的信号如何对应基因和结构？ | 至少三个条件、基因轨道和结构轨道，覆盖全基因组的图 |
| 四/五/六任选 | 20 | 条件差异 / 超分辨 / 三维重建 | 所选任务对应的脚本、指标和图表 |

建议选任务四的“差异定位”，与任务三共用条件数据、预处理和绘图模块。若无法取得额外条件，可以选任务五的合成降采样实验，但这仍不能补足任务三的三个条件要求。

最终需分别提交：代码 zip、用 PPT 讲解的视频、实验报告；报告需有设计思路、对照实验、评价、成员贡献百分比。文档安排为两周，评分强调设计论证与可复现性。

## 2. 仓库实际状态

仓库有 README、LICENSE、通用 Python `.gitignore`、方案 PDF，以及 `micro-c数据/`。尚无分析脚本、训练代码、依赖配置或实验结果。

### 已有接触矩阵

| 项目 | rep1 | rep2 |
|---|---:|---:|
| 文件名 | GSE272159_37C_rep1.mapq_30.10.cool | GSE272159_37C_rep2.mapq_30.10.cool |
| 文件大小，十进制 MB | 482.25 | 468.35 |
| bin 大小 | 10 bp | 10 bp |
| bin 数量 | 464,166 | 464,166 |
| 非零存储记录 | 257,522,134 | 249,673,544 |
| 元数据中的计数总和 | 368,695,972 | 358,452,621 |

两者基因组均为 MG1655，染色体键是 `NC_000913.3`，长度 4,641,652 bp，存储方式为 `symmetric-upper`。只检查了元数据与少量记录，尚未完整扫描质量。

两个文件的 bins 都没有 `weight` 列。读取原始计数需显式使用 `balance=False`；需要平衡后的数据时，先设计过滤与平衡流程，记录收敛情况。Cooler 的区域查询与平衡接口见[官方文档](https://cooler.readthedocs.io/en/latest/api.html)。

不能将全基因组 10 bp 矩阵直接转成稠密数组：仅一个 float32 数组就约 861.8 GB。当前环境约 15 GiB 内存，应采用分块聚合和局部读取。压缩文件体积小不代表全量解压到内存也小。

### 已有标注

`标注数据.xlsx` 中实际有效结构条目与 PDF 的 344 条一致：

| 工作表 | 类型 | 数量 | 长度最小 / 中位 / 最大，bp |
|---|---|---:|---|
| Supplementary Table 4 | OPCID | 68 | 1,220 / 4,595 / 16,660 |
| Supplementary Table 5 | CHIN | 250 | 1,020 / 2,080 / 11,420 |
| Supplementary Table 6 | CHID | 26 | 3,520 / 8,030 / 18,280 |

注意：

- 工作表标称有 1,000 行，许多是空行，应按有效 ID 过滤。
- Table 5 的列是 Start、Center、End，与 Table 4/6 不同，必须按列名解析。
- Excel 的染色体写作 MG1655，需要显式映射到 Cooler 的 NC_000913.3。
- 所有有效区间都满足数值边界，但尚未核实原表采用 0-based 还是 1-based。转换前查原论文补充说明；不能仅凭数值猜测。
- Table 1 已含基因名、位置和链方向，可以先用来画基因轨道；其覆盖完整性与坐标约定仍应核查。
- Table 8 是另外的 Chromosight CHIN 列表，不应直接混入这 344 条，改变任务定义。
- 类别极不平衡，永远预测 CHIN 就能达到约 72.7% 准确率。必须同时报告 macro-F1、每类召回率和混淆矩阵。

### 缺少什么

目前缺少额外实验条件的矩阵、清洗后的 `structures.csv`、可复现环境和处理流水线。rep1/rep2 是同一条件的重复，不能当作两个不同条件。

[GSE272159 官方页面](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE272159) 列有野生型、热应激、蛋白缺失和药物处理样本，可用于补充条件。具体文件和样本名称应再次对应核验，不能把课程文件中的突变名称直接等同于某个 GEO 样本。

## 3. 建议的技术路线

```text
cool 文件 + Excel 标注
        ↓
数据检查 → 标准化坐标 → 多分辨率矩阵 → 局部窗口与归一化
        ├─ 已知窗口 → 简单基线 → 小型 CNN → 分类评价与显著性图
        ├─ 全基因组局部扫描 → 自编码器/形态评分 → 聚类 → rep2 验证
        └─ 多条件信号 → 多轨道图 → 已知结构差异定位（选做四）
```

先做一个可解释、可复现的小模型闭环。DINOv2、图神经网络、扩散模型并不是必需项；PDF 第 13 页给出的是参考路线及参考结果，不是本项目已取得的结果。

### 步骤一：整理数据和环境

1. 建立样本清单，记录文件路径、条件、重复、参考基因组、分辨率。
2. 导出 `structures.csv`：`structure_id,type,chrom,start,end,center,length_bp`，保留源表和原始坐标。
3. 检查重复 ID、越界、空行、类别分布、结构之间的重叠。CHIN 与 CHID 可以存在嵌套，不能把跨类型重叠直接当作脏数据删除。
4. 建立独立 Python 环境，实际安装后固定依赖版本；最先只需要 cooler、NumPy、pandas、openpyxl、matplotlib，模型阶段再加入 PyTorch、scikit-learn。
5. 将原始大文件与生成产物放入适当的忽略规则，代码仓库保留样本清单和获取说明。

验收：有效结构恰好 344 条，类型数量 68/250/26，两个重复的 bin 坐标一致，坐标约定明确。

### 步骤二：读懂并画出局部矩阵

1. 每类先挑 3–5 个结构，在 rep1/rep2 同坐标画热图，并画长度、距离范围相近的未注释背景。
2. 先尝试 50 或 100 bp 聚合分辨率，保留原始 10 bp 数据做重点区域复核。聚合按计数求和，不把彩色 PNG 当作原始输入。
3. 比较原始计数的 `log1p`、深度归一化、按基因组距离计算的 O/E。O/E 表示观测接触强度除以该距离的平均背景，可减弱近距离天然更强的影响；计算期望时应计入零值位置，不能只平均非零记录。
4. 记录低覆盖掩码、主对角线处理、色标与分辨率。计数深度归一化、矩阵平衡和 O/E 解决不同问题，不应混为一谈。
5. 环状基因组跨原点的窗口需要拼接读取；距离背景应考虑环状距离。若首版尚不支持，明确排除区间与覆盖率，后续补齐全基因组处理。

验收：得到能标出基因组坐标、结构边界且两个重复可比较的示例图；无整条染色体的高分辨率稠密读取。

### 步骤三：准备无泄漏的训练与评价数据

1. 先划分基因组区段或窗口重叠组，再切窗、增强；同一结构的两个重复与所有增强版本归入同一集合。
2. 对分区边界设置与最大窗口相匹配的隔离带，避免训练窗口与测试窗口共享原始像素。记录最终每类样本数，必要时使用分组交叉验证。
3. 将局部数值矩阵整理成固定张量。可比较固定物理窗口与结构尺度窗口；现有结构最长约 18.3 kb，单一 10 kb 窗口无法完整包含所有结构。
4. 起步可用小尺度与约 20–25 kb 大尺度双窗口，缩放到 64×64 或 128×128，并保留原始尺度元数据。具体尺度由图像检查和验证集选择。
5. 对照“只用长度/总接触量”的分类器，检查模型是否仅依赖大小和密度。缩放、补零或裁剪规则也可能泄露标签。

验收：输出独立的 split 清单；训练、验证、测试区域不重叠；测试集未用于选参数。

### 步骤四：完成任务一

1. 建立多数类基线，再做形态特征或 PCA 加简单分类器。
2. 训练小型 CNN，可采用三组卷积模块、全局池化和三分类输出；类别权重仅用训练集计算。
3. 报告准确率、macro-F1、每类召回率、混淆矩阵，并报告重复运行或不同分组的波动。CHID 仅 26 条，单次划分结果可能不稳定。
4. 用显著性图或 Grad-CAM 展示每类预测正确与错误的例子；配合遮挡结构区域与遮挡背景的实验，检查模型依据。

验收：训练与评价脚本、权重、数值指标和解释图齐全。若未超过简单基线，应如实分析，而不是只报好看的一次准确率。

三分类器只回答“三类中最像哪类”，不能可靠地回答“是否为未知类型”。低置信度只能作为候选信号。

### 步骤五：完成任务二

1. 从沿对角线的多尺度窗口扫描开始，明确首版主要搜索局部结构；远距离非对角线结构需要额外扫描，不能声称已覆盖所有二维相互作用。
2. 从 rep1 的训练区段采样窗口训练卷积自编码器，用重建误差产生候选；与局部对比度、条纹或块状特征等简单评分比较。未注释窗口不是确定的纯背景，可能含未知结构。
3. 检测阶段先保留已知结构，计算各类型候选召回率及候选数量/覆盖率曲线；不能用“把全基因组都选上”证明有效。
4. 用自编码器或 CNN 的中间特征作为表征，PCA 后做 K-means 或 HDBSCAN。UMAP 可用于展示，不能仅凭二维图的分离断言新类型。
5. 合并相邻重叠候选，区分独立基因组位点和同一结构的多个滑窗；列出与已知注释的重叠、形态相似性和分类器结果。
6. 在 rep1 锁定候选坐标与阈值后，读取 rep2 同位置，计算掩码后的 O/E 上三角相关性，排除主对角线及预设近对角线范围；与距离和覆盖度匹配的背景比较。零方差窗口应标记无效。
7. 候选簇需有多个独立成员、形态一致、两个重复可见，并对已知类型有清楚的区分依据。成员数阈值例如 5 只是可测试的约定，不是生物学标准；不能把相邻五个窗口算作五个成员。

验收：`candidates.csv`、簇成员表、各类已知结构召回、重复一致性及热图。输出字段包括坐标、尺度、候选分数、簇、已知结构关系、rep1/rep2 指标、质量标记。

未注释不等于新的结构类型，重复性高也可能源于共同偏差。成果应称“候选新结构”，明确证据边界。即使未发现可靠新类型，也能按 PDF 第 10 页的最低要求展示已知结构复现，报告完整流程和负结果。

### 步骤六：任务三与选做任务四一起做

1. 补充两个额外条件，优先选能形成明确生物学对照且有重复的条件，核对基因组版本和处理含义。
2. 使用统一分辨率与可比的归一化策略；保留每个重复，不要在评价前直接全部合并。
3. 明确定义每个位点的接触强度，例如固定距离带内接触计数之和，并按有效 bin 数与测序深度处理；所有条件使用同一规则。
4. 先做一张约 10 kb 的四面板图：多条件曲线、条件平均信号、基因轨道、结构轨道，再批量覆盖全基因组。基因组长度对应约 465 张图，最后一张允许不足 10 kb。
5. 对已知结构计算处理相对 WT 的效应量，并展示重复间变化和配对热图。只有少量生物学重复时，应谨慎解释显著性，不能把像素或滑窗当成独立生物学重复。

验收：多轨道图集与参数化脚本；差异表包含结构、条件、方向、效应量、重复一致性和质量标记。条件变化支持关联分析，不单凭热图声称确定机制。

## 4. 两周排期

| 时间 | 重点 | 当天可检查的结果 |
|---|---|---|
| 第 1–2 天 | 样本清单、坐标、标注、局部读取 | 344 条标准标注、三类示例图；启动补充条件数据 |
| 第 3–4 天 | 多尺度窗口、归一化与数据划分 | 窗口缓存、split 清单、基线指标 |
| 第 5–6 天 | 已知结构 CNN 和解释 | 权重、混淆矩阵、显著性图 |
| 第 7–9 天 | 候选扫描、聚类与重复验证 | 候选表、召回曲线、rep1/rep2 图 |
| 第 10–11 天 | 多条件轨道与差异定位 | 任务三图集、任务四差异表 |
| 第 12 天 | 对照实验与错误分析 | 分辨率/归一化/模型对照表 |
| 第 13–14 天 | 复现检查、报告、PPT 和视频 | 三份可提交文件 |

上述是按课程两周要求提出的排期，不是已验证的运行耗时；GPU、成员能力、下载情况与训练速度尚未评估。

若两人合作，一人负责数据与可视化，一人负责模型与候选发现，共同检查评价；三人时可独立分出候选发现和验证。先确定共享坐标、归一化与划分规则，再分工实现。

## 5. 第一个可执行里程碑

第一阶段只推进这四件事：

1. 写 `inspect_data.py`，输出矩阵元数据和标注检查报告。
2. 写 `prepare_annotations.py`，经坐标核验后导出 344 条标准标注。
3. 写 `plot_examples.py`，每类 3 个结构 × 2 个重复，共 18 个热图面板，并补充背景对照。
4. 为后续训练输出按基因组区域分组的划分方案。

这一步完成后，就能具体判断数据里的三类结构有什么区别、窗口应该取多大、归一化是否保留形状，再进入训练。当前这份分析尚未执行上述脚本或训练。
