## 坐标约定与待核实事项

项目内部约定：`start` 为 0-based 包含端点，`end` 为不包含端点，
`length_bp=end-start`。染色体别名 `MG1655` 映射到 `NC_000913.3`，长度 4,641,652 bp。
Cooler 的 bin 表从 0 开始，已经通过全量坐标检查。

Excel 的结构坐标来源约定仍未核实。表头仅标 Start、Center、End，没有注明
0-based/1-based 或端点是否包含。已查论文入口，但未得到可靠的坐标声明。
因此目前采用**显式暂定约定**：保留结构原始数值，解释为 0-based 左闭右开。
边界落在 10 bp 的整数倍本身不足以证明坐标约定。

每条记录保留原始 start/end/center、源文件、源表、源行及 `coordinate_status`。
CHIN 使用原表 Center；另外两类用区间中点，奇数长度时允许半整数。
若确认源坐标为 1-based 闭区间，将配置的 `source_coordinate_system` 改为
`1-based-closed`，脚本会将 Start 和给定 Center 减 1，End 保持不变。
只有获得明确来源依据后，才把状态改成 `verified`，并在配置备注中记录依据。

当前仍不满足原路线中“来源坐标约定已明确”的严格验收条件；其他数据整理可继续使用，
但涉及精确边界的分析与最终发布前应解决这一项。

## 脚本检查内容

执行 `.venv/bin/python scripts/prepare_data.py`：

1. 核对每个 Cooler 的基因组、染色体长度、分辨率、存储方式和像素列长度。
2. 检查全部 464,166 个 bin 的 start/end/chrom，以及索引单调性和末端偏移。
3. 比较两个重复完整 bin 坐标的标准化哈希。
4. 使用 Cooler API 读取 50,000–51,000 bp 窗口，验证形状、对称性、有限值与非负值。
5. 按列名读取 Table 4/5/6，跳过无结构字段的空行，拒绝缺字段、重复 ID、非整数或越界坐标。
6. 验证 OPCID=68、CHIN=250、CHID=26；输出所有重叠区间对，保留嵌套与跨类型重叠。
7. 生成输入 SHA256、样本表、标注表与 JSON 报告。

任何必需检查失败都会抛出错误；输出在全部检查成功之后生成。
这不是完整像素质量控制：没有遍历所有接触计数，也没有完成覆盖度、距离衰减、重复相关性分析。
这部分属于下一阶段。原文件没有 weight 列，局部读取必须使用 `balance=False`。

## 输出与版本控制

- `data/processed/structures.csv`：344 条结构，项目内部坐标及原始来源。
- `data/processed/samples.csv`：样本、条件、重复、组装、文件路径、分辨率、大小、校验和。
- `data/processed/structure_overlaps.csv`：重叠结构对；后续划分数据集时用于避免泄漏。
- `reports/data_audit.json`：检查范围、计数、文件哈希、警告与坐标状态。

这些小型文本产物可以随代码提交；原始输入、窗口缓存、权重和大结果目录忽略。
本阶段不移动、修改或合并两个生物学重复。

## 环境

`.venv` 为项目独立环境。`requirements.in` 是直接依赖列表，`requirements.txt`
由已安装环境 `pip freeze` 生成。`requirements-build.txt` 固定构建依赖，
供 asciitree 等源代码包安装使用；安装时使用 `--no-build-isolation`，复用固定构建工具。

验证命令：

```bash
.venv/bin/python -m pip check
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/prepare_data.py
```

PyTorch、训练加速与 GPU 尚未安装或验证，本阶段只建立数据处理环境。
